SLIDE 14: ESP32 Sensor Array & Pinout Details
--------------------------------------------------------------------------------
[Visual Layout]:
A schematic diagram of the ESP32 showing pin connections to the sensor array.

[Slide Content]:
* Temperature & Humidity: DHT11 (GPIO 14).
* Seismic Motion: MPU6050 Accelerometer (GPIO 21/22 - I2C).
* Water Level: Parallel resistive sensor (GPIO 34 - Analog).
* Soil Moisture: Resistive probe (GPIO 35 - Analog).
* Rainfall Intensity: Inverted rain gauge (GPIO 33 - Analog).

[Presenter Notes]:
"We configure the ESP32 with a multi-sensor array to track temperature, humidity, seismic movement, water levels, and rainfall. Pin configurations are optimized to ensure stable operation during boot."

SLIDE 15: Adaptive Power Throttling Algorithm
--------------------------------------------------------------------------------
[Visual Layout]:
A flowchart showing how the ESP32 switches between active (5s) and idle (30s) sleep intervals based on sensor activity.

[Slide Content]:
* Power Constraint: Field stations run on solar-charged battery systems.
* Hysteresis Checking: Sensors are polled regularly and compared with baseline readings.
* Active Mode (5s): Triggered by environmental changes or threshold violations.
* Sleep Mode (30s): Standard interval when sensor readings remain stable.

[Presenter Notes]:
"To extend battery life, the ESP32 firmware uses an adaptive throttling algorithm. The node sleeps for 30-second intervals when conditions are stable, but switches to 5-second polling when changes are detected."

* Challenge: Blocked GPS permissions caused Next.js to crash during development.

* Solution: Implemented `console.warn` loggers and added fallback UI states (denied/pending) to maintain app stability.

[Presenter Notes]:
"One of the challenges we resolved was handling blocked GPS permissions. By replacing standard console error calls with warning logs and fallbacks, we kept the application running smoothly even when location access was denied."
